| Profile or probe                                           | What is established                                                                                                                     | What remains unknown                                                                                                                                                     |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `restricted-reader`                                        | Default configuration; live execution is **blocked**.                                                                                   | This distribution cannot independently establish no-write effective grants. | `operator-assisted-local`                                  | Explicit `--profile operator-assisted-local` plus `--live` is required on every live invocation; runner operations stay reviewed reads. | Effective credential reach and host isolation are not proven. The operator must accept the limited guarantee or use credential-isolated collection.                      |
| `GET /user` for OAuth or other user tokens                 | A returned login can verify the user principal, including comparison to a declared principal when configured.                           | Resource grants, organization role, full repository access, and absence of write reach.                                                                                  |
| `GET /installation/repositories` for an installation token | Token access to the returned installation repositories.                                                                                 | It does not independently verify installation principal identity or complete effective grants. Unverified installation identity cannot be reused by live resume/refresh. |

The sole credential source is `gh-cli`. `node src/cli.ts auth-plan SCENARIO_ID --org ORG` is an offline plan, not authentication or grant verification. The reviewed collector resolves the intended github.com credential privately only after live/profile/class gates. GitHub CLI's normal stored-token/environment precedence remains relevant; the declared class must describe the credential actually selected. Never retrieve a token through the conversational adapter, dump the environment, or store a token in prompts, configuration, receipts, or arguments. Never automatically log in, refresh grants, switch accounts, or escalate credential classes. See [authentication](authentication.md).

Standard GitHub CLI OAuth grants such as `repo`, `read:org`, and `gist` may include broad write reach. Read-only collector operations do not make those credentials read-only. OAuth is an accepted explicit credential-class declaration, not a certification of grants or billing access. Other accepted declarations remain classic PAT, fine-grained PAT, App user, and App installation; these declarations do not prove GitHub CLI provisioning, endpoint access, or effective grants.

### Billing documentation conflict and source contract

The [billing tutorial](https://docs.github.com/en/billing/tutorials/automate-usage-reporting) states organization owner or billing manager and a classic PAT, and says fine-grained PATs are not supported. The [billing introduction](https://docs.github.com/en/billing/get-started/introduction-to-billing) directs users toward fine-grained tokens with endpoint-defined permissions. The exact organization-detail reference reviewed on the date above does not resolve a complete fine-grained/App grant matrix. Do not generalize either statement across endpoints, and do not infer App organization support from the separate [enterprise reference](https://docs.github.com/en/enterprise-cloud@latest/rest/billing/usage).

Accordingly, classic PAT is a documented candidate path for operator-assisted organization reporting, not a verified deployment. Fine-grained PAT, App installation, and App user are accepted credential-class declarations in the runtime, not certified support for this billing endpoint. Their exact acceptance remains pending. Never silently switch credential classes or request a broader token after a denial.

Normal GitHub CLI browser-OAuth billing access is also not established. A signed-in GitHub CLI, a broad OAuth grant, or a successful identity read does not resolve organization role, billing-platform eligibility, or this exact endpoint's token acceptance.

The reviewed detail response has `usageItems` with date, product, SKU, quantity, unit type, unit price, gross/discount/net amounts, organization, and optional repository identity. It does not document a currency field or a universal currency default. A supplied response currency is retained with provenance; missing currency is null/unspecified, never assumed dollars. A summary endpoint has a different schema and is not a substitute for detail.

The detail reference does not document pagination. An unexpected continuation indicator is an unmodelled contract: preserve validated observations as partial where usable, report the limitation, and neither follow unapproved links nor claim completion. Exact reconciliation does not establish finality, invoice completeness, or missing-partition values.

### Rate limits and GraphQL

Honor REST `Retry-After` and reset headers and distinguish ordinary permission denials from retryable failures. Reviewed GraphQL queries retain every modeled cursor and inspect errors even on HTTP 200. GraphQL `RateLimit.resetAt` is an ISO DateTime field; do not parse it as the epoch-seconds REST `x-ratelimit-reset` header. The schema type is authoritative when explanatory prose differs. Sources: [REST best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api), [GraphQL RateLimit](https://docs.github.com/en/graphql/reference/objects#ratelimit), [DateTime scalar](https://docs.github.com/en/graphql/reference/scalars#datetime).
